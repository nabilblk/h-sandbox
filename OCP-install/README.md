# Harakiri OpenShift Install Package

This folder contains the OpenShift installation assets used for customer
handoffs. The canonical package is:

```text
OCP-install/harakiri-security/
```

It installs PostgreSQL, Keycloak, OpenSandbox, Harakiri Sandbox, and optional
BackgroundAgent into one namespace. It does not create or modify Security
Context Constraints.

`OCP-install/install-restricted.sh` is kept as a compatibility wrapper and
delegates to `OCP-install/harakiri-security/install.sh`.

## Install Order

The package follows the order ops teams usually need:

1. Copy images from the source Harbor to the client registry when they differ.
2. Download Helm charts locally into `OCP-install/charts/`.
3. Install PostgreSQL and Keycloak.
4. Install OpenSandbox.
5. Install Harakiri Sandbox.
6. Install BackgroundAgent configured for Harakiri, when enabled.
7. Create OpenShift Routes and run smoke checks.

## Files

| File | Purpose |
| --- | --- |
| `harakiri-security/install.sh` | Canonical one-namespace installer. |
| `harakiri-security/00-postgres.yaml` | OpenShift-compatible PostgreSQL manifest. |
| `harakiri-security/01-keycloak.yaml` | Keycloak deployment and service; realms are generated by the installer. |
| `harakiri-security/02-opensandbox-values.yaml` | OpenSandbox values for one namespace. |
| `harakiri-security/03-harakiri-values.yaml` | Harakiri Sandbox chart values for restricted OpenShift. |
| `harakiri-security/04-background-agent-values.yaml` | BackgroundAgent values wired to Harakiri Sandbox. |
| `harakiri-security/05-routes.yaml` | OpenShift Routes for web, API, auth, BackgroundAgent, and sandbox wildcard. |
| `mirror-opensandbox-chart.sh` | Mirrors the upstream OpenSandbox chart into Harbor without patching it. |
| `charts/` | Created by the installer; ignored by git. |

## Default Registry And Charts

Default internal registry:

```text
https://core.campus.clusterdiali.me/
```

Default chart refs:

```text
OPEN_SANDBOX_CHART_REF=oci://core.campus.clusterdiali.me/harakiri/charts/opensandbox
OPEN_SANDBOX_CHART_VERSION=0.2.2
SANDBOX_CHART_REF=oci://core.campus.clusterdiali.me/harakiri/charts/harakiri
BACKGROUND_AGENT_CHART_REF=oci://core.campus.clusterdiali.me/harakiri/background-agents/charts/harakiri
```

The current package defaults still allow the locally published Harakiri chart
and image tags to be overridden independently:

```bash
SANDBOX_CHART_VERSION=<harakiri-chart-version>
SANDBOX_IMAGE_TAG=<harakiri-image-tag>
BACKGROUND_AGENT_CHART_VERSION=<background-agent-chart-version>
BACKGROUND_AGENT_IMAGE_TAG=<background-agent-image-tag>
```

For an external release handoff, set the Harakiri chart version and image tag to
the same release version.

## Run

```bash
CLIENT_REGISTRY_USERNAME=<robot-or-admin> \
CLIENT_REGISTRY_PASSWORD=<token> \
POSTGRES_PASSWORD=<generated-password> \
KEYCLOAK_ADMIN_PASSWORD=<generated-password> \
OPEN_SANDBOX_API_KEY=<generated-token> \
BACKGROUND_AGENT_WORKSPACE=/path/to/background-agents \
./OCP-install/harakiri-security/install.sh
```

Client clusters should log in with `oc` first and pass explicit hostnames,
versions, and credentials through environment variables:

```bash
OPENSHIFT_LOGIN=false \
NAMESPACE=harakiri-security \
CLIENT_REGISTRY_URL=https://core.campus.clusterdiali.me/ \
CLIENT_REGISTRY_USERNAME=<robot-or-admin> \
CLIENT_REGISTRY_PASSWORD=<token> \
POSTGRES_PASSWORD=<generated-password> \
KEYCLOAK_ADMIN_PASSWORD=<generated-password> \
OPEN_SANDBOX_API_KEY=<generated-token> \
BACKGROUND_AGENT_WORKSPACE=/path/to/background-agents \
WEB_HOST=hs.apps.example.com \
API_HOST=hs-api.apps.example.com \
AUTH_HOST=hs-auth.apps.example.com \
BACKGROUND_AGENT_HOST=hs-background-agent.apps.example.com \
SBX_DOMAIN=hs-sbx.apps.example.com \
./OCP-install/harakiri-security/install.sh
```

The installer performs HTTP health checks by default. To add a sandbox
create/run/kill smoke, set `SANDBOX_SMOKE_TEST=true` and provide
`HARAKIRI_API_KEY` for an API key that already exists in the Harakiri
workspace. For a local-only demo you may set `HARAKIRI_SEED_ON_BOOT=1`, but
production installs should create users and API keys deliberately after
Keycloak login.

To create an optional first Keycloak user during a lab install, pass
`BOOTSTRAP_USER_EMAIL` and `BOOTSTRAP_USER_PASSWORD`. The generated password is
temporary and must be changed on first login.

## Security Model

This package does not modify default OpenShift SCCs.

OpenSandbox egress `dns+nft` needs a NET_ADMIN sidecar. The restricted profile
sets `OPEN_SANDBOX_SEND_OPEN_NETWORK_POLICY=0` so open-network sandboxes do not
request that sidecar. Enforced restricted/custom/blocked egress requires a
client-approved runtime profile or a future OpenSandbox egress mode that works
under restricted-v2.

Dockerfile template builds are disabled in this profile. Build template images
outside the cluster, push them to Harbor, then import them with the Harakiri CLI.
