## Qualification

[Source-native run 34707522766](https://github.com/nabilblk/h-sandbox/actions/runs/34707522766)
passed all 11 gates and cleanup on a disposable GitHub-hosted Linux amd64 k0s
fixture. This includes OIDC/S256, an empty-catalog state, actual first-task logs
exactly once, private authenticated metrics, OpenCode model-free SDK/CLI tasks,
unique history, database/workspace and encrypted credential recovery, history
fingerprint restoration, provider interruption, rc.9 binary rollback with schema
039 retained, re-upgrade with a visible gap, logout and key revocation.
It used source-built candidate artifacts and does not itself qualify publication.
The [source-native receipt](../operations/evidence/standalone-34707522766.json)
is retained in Git rather than relying only on expiring Actions artifacts.

[Published run 34708761898](https://github.com/nabilblk/h-sandbox/actions/runs/34708761898)
passed the first nine gates, including recovery and provider interruption. Its
final compatibility gate failed before qualification; cleanup passed. The
old-SDK import also initialized a second Playwright runtime. The harness fix
separates SDK-only imports without changing any application artifact.

**Published qualification passed:** [run 34709727741](https://github.com/nabilblk/h-sandbox/actions/runs/34709727741)
passed all 11 gates and cleanup in 14m32s. The
[retained receipt](../operations/evidence/standalone-34709727741.json) identifies
the exact baseline, candidate manifest, image indexes, source and schema. It
verifies published rc.9 -> rc.10 -> rc.9 -> rc.10, with schema 039 retained:
old SDK/new API, files/keys/capacity preservation, identical restored history,
and an explicit collection gap during older binaries. Both encrypted/provider
recovery and real onboarding were rerun using actual published SDK/CLI packages.
The failed attempt remains a failed attempt, not a substituted success receipt.

Earlier failures remain recorded rather than reclassified: the PostgreSQL
fixture needed an explicit UUID cast; the empty-catalog fixture had to account
for legacy migration seeds; native onboarding found and fixed a real detached-log
read bug; and rc.9's unknown history route returns exact `403 forbidden`, not
404, after valid legacy reads. No admission/auth assertion was weakened to
accept unrelated HTTP failures. [PR 45's qualification note](https://github.com/nabilblk/h-sandbox/pull/45#issuecomment-5647511807)
links the underlying attempts.

The 50,000-operation PostgreSQL fixture measured history p95 337 ms over ten
queries; three matched observer trials passed the 15% median admission/cleanup
budget. These are controlled measurements, not production SLAs or arbitrary
scale qualification. No HA, general CSI, restricted OpenShift, schema
down-migration or every provider's pause/snapshot/restore combination is implied.

## Public k0s Delivery

The application bundle was deployed at Harakiri Helm revision **41**. API,
scheduler, template-builder and web became ready with the published RC.10
indexes. Explicit kubeconfig and namespace-UID checks selected the public lab,
not the default CRC context. Structured preflight compared rendered resources,
preserved operator settings/secrets/public origins and verified that PostgreSQL,
registry, Keycloak and provider deployment identities/specifications were
unchanged. Neither the cluster nor tunnel was restarted.

An encrypted pre-upgrade database/operator backup and a separate encryption key
were retained privately. Archive checksums, GCM verification and full PostgreSQL
archive decoding passed. This application-upgrade backup is not a newly
coordinated four-part disaster-recovery point; no destructive restore ran in the lab.

The first public web check returned 502 during the pod/forward handoff. The API
and public OIDC discovery remained healthy, and the next web check returned 200
without restarting the tunnel. This was not a zero-downtime deployment.

One owned Python-template sandbox passed actual published SDK/CLI checks:
idempotent create identity, file round-trip, expected command output, history and
CLI usage JSON. Its covered history recorded one accepted create, peak one,
28.499 held slot-seconds and one independent readiness observation. The runtime
was terminated and its scoped, expiring test key revoked; live capacity returned
to zero. The requested preferred agent template was absent from this lab's
catalog; that first attempt created no runtime and revoked its key before using
an existing installed template. Native acceptance separately exercises OpenCode.

Usage was inspected at 1440, 390 and 320 pixels with no page-level horizontal
overflow; 24-hour, 7-day and 30-day views loaded. The initial chart correctly
marks pre-upgrade time as missing coverage. These screenshots are not benchmarks.
Public logout removed dashboard access. Sign-in then reached the public
`sb-auth.harakiri.io` authorization endpoint with code flow and PKCE S256,
returned to `sb.harakiri.io`, and restored the authenticated Usage route.
No legacy access token remained in local storage.

## Documentation and Remaining Operations

Public concepts, tutorial, API/SDK/CLI access and private monitoring guidance
ship with RC.10. The follow-up installation/preview guides pin current packages
and preserve the tested rc.9 bootstrap before an explicit checksum-verified
rc.10 upgrade. Original release artifacts and tags are not overwritten by
documentation-only delivery.
Local follow-up verification passed 98 web tests, typecheck/build and eight
documentation browser checks, including all pages at 1440/390/320 pixels.

Physical Harbor disk/inode headroom still needs operator-side evidence and
monitoring. Successful registry pushes and anonymous downloads prove current
artifact availability, not durable storage capacity. Optional metrics remain
disabled in the public lab; enabled authenticated collection was tested only in
the disposable profile. Stable promotion remains a separate owner decision.
