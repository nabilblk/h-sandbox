# v0.5.0-rc.3: Reliable Sandbox Renewal

September 7, 2026. **Prerelease, not stable.** Supersedes rc.2 for acceptance
testing; existing stable tags and old release artifacts must not move.

## Changes

- Fixed expiration at an old idle schedule after successful renewal. API renewal,
  retries, command activity, terminal keepalive and expiration coordinate through
  the same PostgreSQL row lock and confirmed native deadline.
- Added optional renewal idempotency keys, guarded retry completion, and recovery
  when native renewal succeeds but the database commit fails. Provider failures
  propagate even with the legacy fallback setting enabled.
- Commands and sessions renew before starting; attached terminals keep renewing
  until detached. Failed keepalive closes the connection with an explicit error.
  Reading status or following output does not renew a sandbox. Long/detached
  jobs still need enough initial TTL or explicit renewal before expiry.
- Preserved the 10-second product TTL independently of OpenSandbox's longer
  minimum creation lease. A stale lifecycle response cannot revive an expired row.
- Added first-class workspace concepts, reference and operator guides, plus
  technical documentation and runnable renewal acceptance checks.

## Required Upgrade Order

Back up PostgreSQL and capture current Helm values privately. Stop the old
scheduler, apply additive migration `036_sandbox_provider_expiration.sql`, then
deploy matching rc.3 API and scheduler binaries. The builder reuses the API
image. Never run the old scheduler alongside the corrected API.

Existing rows adopt their native deadline once conservatively. A legacy short
TTL can last until that deadline during the transition; new sandboxes preserve
the requested short TTL. Downgrading restores the original defect even if the
new column is retained. Prefer forward recovery. See
[lease coordination](../sandbox-lease-operations.md) for failure and rollback behavior.

required. In a fresh consumer directory:

```bash
gh release download v0.5.0-rc.3 --repo nabilblk/h-sandbox --pattern '*.tgz' --pattern SHA256SUMS
shasum -a 256 -c SHA256SUMS
npm init -y
npm install ./h-sandbox-sdk-0.5.0-rc.3.tgz ./h-sandbox-cli-0.5.0-rc.3.tgz
./node_modules/.bin/harakiri --version
```

npm publishing requires separate authorization. Verify both exact versions exist
before using registry installation; do not assume `next` is available or promote
`latest`. npm remains blocked by authentication. Harbor/GitHub publication, k0s
revision 25, immutable digests and deployed runtime verification are recorded in
the [delivery receipt](./0.5.0-rc.3-delivery.md).

## Verification and Remaining Gates

Source verification passed 526 workspace tests (two database-gated skips), all
19 dedicated PostgreSQL lease/workspace tests, typecheck and build. Isolated real
OpenSandbox runs proved renewal beyond the original deadline without intervening
activity, final expiration, the 10-second product TTL and terminal keepalive.
These are source acceptance results, not a claim that every cluster is upgraded.

Restricted OpenShift storage/UID acceptance, OpenCode amd64 template acceptance,
host login/reboot recovery, coherent DB/PVC rollback, and the dashboard Commands
default working-directory follow-up remain open. Persistent workspace archive
retains storage and allocation; snapshot/restore of workspace-backed sandboxes
is not supported. BackgroundAgent is outside this release's deployment scope.
