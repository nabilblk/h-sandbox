### Initial Failures Retained

- The first fixture run passed all three SDK scenarios. Its CLI runtime was
  created successfully, but the harness incorrectly parsed progress text as
  the sandbox ID. Cleanup used the owned ID, confirmed capacity zero and revoked
  the key. The corrected harness reads the CLI's structured saved sandbox ID;
  the complete repeat passed. No product mutation was retried to disguise this.
- Immediately after public deployment, a baseline capacity GET and the first
  documentation navigation returned Cloudflare 502 while supervised local
  forwards reconnected to replacement pods. No sandbox creation had been sent
  in that failed public attempt. Its temporary credential was subsequently
  revoked and absence of owned runtimes confirmed.
- After the forwarding handoff, five consecutive API read checks passed. The
  complete native run and all seven documentation browser checks passed on
  repeat. The initial documentation run had six passes and one gateway failure.
  This is explicitly not evidence of zero-downtime deployment.

All twelve runtimes created across delivery attempts were subsequently absent
from the provider. Test credentials were revoked and temporary public test
memberships removed. Non-executing audit records remain. Only owned browser
sessions and forwards were closed, and the isolated acceptance VM was returned
to its original stopped state. The public cluster and tunnel remain running.

## Remaining Boundaries

- Harbor disk/inode headroom and durable monitoring remain unverified. Uploads
  succeeded, but no host access was available to establish storage capacity.
  No tagged artifacts, Docker data or unrelated workloads were pruned.
  An owner-requested retest at 15:10 UTC found all eight Harbor components
  healthy, read-only mode off and no configured project storage quota limit.
  Two independent 8 MiB in-progress blob writes returned 202 with their full
  byte ranges; each cancellation returned 204 and subsequent lookup 404.
  No image or tag was created. The earlier disk-full error was not reproduced.
  `/api/v2.0/systeminfo/volumes` returned `{"storage":[{}]}`, so the working
  registry is not evidence of expanded physical storage or inode headroom.
- Native runtime acceptance was arm64. Publishing amd64 image manifests does
  not certify native amd64 execution.
- Optional native pause/snapshot/Vault combinations, restricted OpenShift
  enforcement, HA/CSI recovery and full encrypted Vault recovery are not newly
  certified by this release.
- Migration 038 still requires coordinated activation from pre-capacity rc.8;
  do not reopen old writers or automatically roll back to pre-capacity images.
- The hosted lab has no uptime SLA. Its transient forwarding handoff remains
  operational evidence, not a fixed availability guarantee.
