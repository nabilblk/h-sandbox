# 0.5.0-rc.12: Reliable Framework Workflows

September 26, 2026. Developer Preview on npm `next`; SDK/CLI stable `latest`
remains `0.4.0`. The independently versioned Deep Agents adapter is `0.1.0-rc.2`.
The [delivery receipt](0.5.0-rc.12-delivery.md) records successful publication,
verified artifacts and the local web/documentation rollout. The
[completed release plan](../exec-plans/completed/reliable-framework-workflows-release.md)
records scope and decisions. This feature list alone is not publication evidence.

## What Changes

- SDK JSON requests default to a 120-second deadline covering both fetch and
  body consumption. Client and primary command/file/lifecycle calls accept
  `requestTimeoutMs` and `signal`. Local expiry raises
  `HarakiriRequestTimeoutError`, not a fabricated remote execution failure.
- Adapter observation includes final logs. Acknowledged command references,
  partial-transfer paths and original causes survive transport and cancellation
  failures. Disposable-task cleanup has its own cancellation context.
- A three-module application example uses real `createDeepAgent` and official
  `PostgresSaver` checkpoints: separate workers, checkpoint-bound human decisions,
  tenant isolation, read-only command recovery and explicit file recovery after TTL.
  PostgreSQL is not a core SDK or adapter runtime dependency.
- Public guides distinguish model calls, application state, runtime effects and
  retained files. A weekly compatibility probe reports drift without silently
  widening supported framework peers.

## Install And Migrate

```sh
npm install --save-exact @h-sandbox/sdk@0.5.0-rc.12
npm install --global @h-sandbox/cli@0.5.0-rc.12

# Optional framework backend, installed with its exact peers:
npm install --save-exact @h-sandbox/deepagents@0.1.0-rc.2 \
  @h-sandbox/sdk@0.5.0-rc.12 deepagents@1.14.0
```

Use Node 22 or 24 LTS and commit the application lockfile. Node 20 remains only
a legacy consumer check. The CLI is republished with its matching SDK, not a new
set of CLI commands. Standard SDK operations require API rc.9 or newer; usage
history requires rc.10. The adapter pins Deep Agents 1.14.0 and SDK rc.12 exactly.

**Request deadlines are a behavior change.** A foreground command longer than
120 seconds needs a larger `requestTimeoutMs`, or use detached execution and
bounded observation. A local abort/timeout neither kills remote work nor proves
that a mutation failed. Do not blindly retry a lost submission. SSE and raw route
requests retain separate controls. Model, callback and database deadlines are
application-owned.

Use application-owned sandboxes for approval pauses, not the disposable-task
helper. Checkpoints do not extend TTL. After worker loss, observe acknowledged
command IDs rather than replaying the graph. Retained-file replacement creates
a new runtime; old command IDs and graph bindings do not transfer. No distributed
exactly-once guarantee is made.

## Evidence And Operator Scope

The [implementation receipt](reliable-framework-workflows.md) records two
successful isolated native amd64 runs, each with 16 gates and cleanup. They cover
real PostgreSQL, worker loss after command acknowledgement, real server-side
expiry, retained-file replacement and an independently verified Qwen3 4B repair.
Recovery decisions are scripted; the model repair is a separate gate. The baseline
is published API rc.9, not a newly qualified server pair or OpenShift profile.

No API behavior, database schema or Helm template change is introduced relative
to rc.10. Full distributions align image/chart versions; the existing local lab
only needs a web/documentation rollout. Preserve operator-owned origins, secrets,
encryption keys and existing workloads. Do not run bootstrap scripts against an
existing deployment. Prior release artifacts remain immutable.

Adapter `latest` remains the previously accepted rc.0 tag; use `next` or the exact
rc.2 version. Do not mistake this release for stable promotion, a model benchmark,
new recovery certification or production availability guarantees.
