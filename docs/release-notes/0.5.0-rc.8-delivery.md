September 9, 2026. Candidate published and deployed; public-source opening and
announcement remain separately gated. Independent evaluation is owner-confirmed.

during rc.7 acceptance. Markdown/JSON documentation and plain-text indexes must
have correct MIME types; missing documentation must return 404, not the SPA shell.

All rc.7 application, SDK and CLI behavior is retained.

## Interventions and Lab Delivery

The first capacity attempt could not schedule a 4 GiB sandbox because upstream
server/gateway requests reserved 12 GiB. The committed evaluation values now use
384 MiB total requests for those services and one gateway. The failed create and
recovery-required workspace were retained in evidence, not silently repaired.
Other retained failed attempts cover the optional `python` alias, absent public
wildcard routing, stale CLI version, Helm docs fallback and a local test launched
before restarting stale port forwards. Corrections and successful reruns are
recorded separately; no fixed time-to-first-task claim is made.

The populated lab reached Helm revision **31**, with API/scheduler/builder rc.8
and the digest-pinned docs web correction ready. Identity origins, config.js,
SMTP and live secret values were preserved. A historical September 5 `kubectl-patch`
field owner on Nginx caused revision 30 to fail; after checking the existing values,
Helm's conflict resolution adopted the reviewed Nginx field without resource
replacement. That partial upgrade had already started a web pod with the old
subPath-mounted file, so the web deployment was restarted once after adoption.
The clean fixture needed neither repair. Brief public 502s during
pod replacement were resolved by restarting the existing supervised port forwards;
this laptop-backed lab offers no uptime SLA.

At 13:02 UTC the public web/API/discovery checks passed, with the expected public
issuer and no localhost runtime-config redirect. All 35 hosted Markdown pages,
the JSON inventory and both LLM indexes returned their intended MIME types;
missing documentation returned 404. Desktop and 390-pixel mobile docs rendering
passed, and the public admin Settings page loaded after the final deployment.

Cleanup completed at 13:06 UTC: no test sandbox pods remained, the retained test
workspace was archived, both test Helm releases and both owned namespaces were
removed, and the isolated VM was stopped/deleted. Private coordinated backups,
checksums and reports were retained. OpenSandbox CRDs were retained by Helm until
the disposable cluster was deleted; no shared-cluster CRDs were removed. The
existing lab VM, user workloads and default kubecontext were not changed.

## Security and Remaining Gates

Grype 0.118.0 with its September 9 database scanned the selected arm64 images.
The API has 211 distribution matches: 7 critical, 50 high, 63 medium, 8 low,
59 negligible and 24 unknown. None of the high/critical matches has an available
fix in that database; no API npm matches remain. The selected web has five medium
matches and no high/critical matches. SBOMs are separate release assets. These
counts are not an exploitability assessment, a blanket waiver or a vulnerability-free
claim. Review vendor advisories before broader exposure; amd64 and the full set of
runtime/dependency/template images do not have an equivalent scan receipt here.

The selected API/web layer review covered 24 compressed layers and 15,058 regular
files (42.33 MB scanned text). Six findings were reviewed as two source/compiled
fixture pairs, one loopback-only smoke credential and one V8 identifier; they
match the earlier inspected candidate. No usable credential was identified in
those layers. Links/devices were recorded rather than followed, and misleadingly
named dpkg plaintext metadata was renamed only in the scan copy. The final scan
completed without parsing errors. This is not a review of every upstream image.

Publication safety remains open for lab credential remediation and external
receipt/monitoring confirmation of the approved private reporting address.
Previously rotated human credentials are distinct from remaining platform keys.
Neither a successful deployment nor the owner's independent evaluation closes
those safety items. Source opening and announcement stay at point 5; no stable
package tag or repository visibility was changed.
