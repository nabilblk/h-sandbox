# 0.5.0-rc.10: Usage Observations and First-Task Onboarding

September 12, 2026. Developer Preview candidate, npm `next`. Stable `latest`
remains `0.4.0`. Publication and deployment evidence belongs in the delivery
receipt; the feature list alone is not evidence of recovery qualification.

## Developer Changes

- Organization history includes unique accepted create/restore/resume operations,
  latest terminal outcomes, held slot-seconds/peak and independent readiness
  observations. Missing coverage is explicit; these are not compute or billing
  measurements. Outcomes can change after a retry of the same operation.
- Read history through `GET /v1/usage/history`, SDK `client.usageHistory()` or
  CLI `harakiri usage --period 24h|7d|30d [--json]`. API keys need `org:read`.
  Existing `GET /v1/usage` clients retain their original response contract.
- The Usage screen includes bounded periods, coverage and accessible bucket
  values. Closing the browser does not stop the scheduler's observer.
- Onboarding uses eligible installed templates, waits for actual execution
  readiness and executes one finite, model-free shell task. Timeout recovery
  retains its sandbox/command identity instead of replaying mutations.
- Optional private API/scheduler metrics use a separate bearer token and
  loopback listener. Default installations need no monitoring stack or CRDs.

## Install and Upgrade

```bash
npm install --save-exact @h-sandbox/sdk@0.5.0-rc.10
npm install --global @h-sandbox/cli@0.5.0-rc.10
helm pull oci://core.campus.clusterdiali.me/harakiri/charts/harakiri \
  --version 0.5.0-rc.10
```

Preserve operator values and Secrets, back up PostgreSQL, and deploy the exact
chart with digest-pinned API/web images. Migration 039 adds tables/indexes under
bounded locks; it does not alter admission rules or remove reservations. API and
scheduler must be upgraded together. Usage collection defaults to enabled with
30-day retention and begins at the collection epoch; it does not invent earlier
history. Short uncovered tails and unobserved short-lived runtimes are expected.

The runtime chart stays `0.2.2-harakiri.2`. This release does not upgrade
PostgreSQL, Keycloak or the runtime provider. Do not replace installation
origins, encryption keys or provider credentials with development defaults.
Retain migration 039 during a qualified binary rollback. Older rc.9 binaries
do not collect history; the interruption must remain an explicit gap.
The rc.9 authorization layer returns `403 forbidden` for the unknown history
route, even for a valid organization reader. This is not a reason to broaden
key scopes: use a matching client/server capability and upgrade the server.
Never reintroduce pre-capacity rc.8 writers after migration 038.
