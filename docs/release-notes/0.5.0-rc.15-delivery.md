## Public Lab

The existing ARM64 k0s release `harakiri` moved from Helm revision **51 to 52**
with the actual rc.15 chart and digest-pinned API/web images. API, scheduler,
template builder and web are ready, with zero restarts on the new pods and
running image IDs matching the verified registry indexes.

Encrypted operator values, managed resources and a PostgreSQL custom-format
dump were captured privately. The dump was refreshed before the upgrade and
verified by decryption and archive table-of-contents inspection. This is not a
coordinated backup of Keycloak or retained workspace files.

Offline rendering and server-side admission allowed only four application
images, the builder job image, release labels and reproduced ConfigMap
checksums. Existing owned cross-namespace and cluster-scoped RBAC objects
received release labels only; their rules and bindings did not change.
All other operator settings, Secret values and public origins were preserved.
Post-upgrade comparison verified **310 protected resources, all 7 PVC identities
and specs, and all 13 unrelated active pod identities/readiness/restart counts**.
The runtime provider, Keycloak, cluster and tunnel were not restarted. The
restricted OpenShift profile was not enabled on the k0s lab.

The public endpoint monitor recorded 114 samples: one web 502 and one API 502
during pod-bound forwarding reconnection, then recovery without manual restart.
Identity discovery stayed available. Final web, API health, OIDC discovery,
OpenAPI and documentation-export requests returned HTTP 200.

The live OpenShift guide and changelog were checked at 1440x1000 and 390x844.
Screenshots were inspected; no horizontal page overflow or uncaught browser
error was found. Sign-in reached the public `sb-auth.harakiri.io` login form,
not localhost. This is redirect/form verification, not a new authenticated
session, logout or refresh-token acceptance test on the lab.

## Client Handoff

1. Read the [public OpenShift guide](https://sb.harakiri.io/#docs/install-openshift)
   and [complete runbook](../install-openshift.md). Prepare an approved isolated
   target and platform-managed PostgreSQL, Keycloak, Secrets and registry trust.
2. Obtain the tagged kit, both chart archives and exact images from the receipt.
   Keep the image digests after mirroring; do not substitute `latest` or rc.14.
3. Install the matching workstation CLI with
   `npm install --global @h-sandbox/cli@0.5.0-rc.15`, review generated resources,
   run the read-only preflight, then install in the documented order.
4. Return the sanitized [qualification checklist](../openshift-qualification.md).
   SCC admission, arbitrary UID, CRI-O, network isolation, protected services and
   cleanup must be observed before claiming production readiness.
