## Public Lab

The target is the existing k0s lab only. Customer OpenShift and BackgroundAgent
are outside this delivery. The pre-upgrade capture includes encrypted Helm
values/resources and a PostgreSQL custom-format dump, verified by decrypting
and reading its table of contents. This is not a coordinated workspace-file
or Keycloak database recovery backup.

The single Helm upgrade moved release `harakiri` from revision **50 to 51** and
installed the actual **rc.14 chart**, with verified rc.14 API/web digests. API,
scheduler, template builder and web are ready. Their running image IDs were
checked. Migration `040_protected_route_uniqueness.sql` is present in the ledger.

Rendering and server-side admission allowed chart/version metadata, the four
application images, the builder job image and reproduced ConfigMap checksums.
All other operator settings and the inspected Secrets were unchanged. Post-upgrade
checks compared 47 protected namespaced resources, preserved all 7 PVC identities
and specs, and verified all 13 unrelated active pod identities/readiness/restarts.
No provider, Keycloak, cluster or tunnel restart was performed. No retained
workspace or customer deployment was changed. The optional OpenWebUI/adapter
Compose stack was not installed in the public lab.

The encrypted database dump was refreshed immediately before the upgrade and its
archive table of contents and encryption round trip verified. Helm hooks were
skipped; the preserved `AUTO_MIGRATE=1` API startup path applied migration 040.
Rollback-on-failure and readiness waiting do not qualify database downgrade.

One web 502 and one API 502 were observed while pod-bound forwards reconnected.
Existing supervision recovered without manual restart. The public OpenWebUI
guide and changelog then loaded successfully at 1440x1000 and 390x844; screenshots
were inspected, no horizontal page overflow or uncaught browser error was found.
Sign-in reached the public `sb-auth.harakiri.io` form, not localhost. This checks
the redirect/form, not an authenticated user workflow or password reset.

Independent operator self-service acceptance remains open. Native workflow
qualification used source-built images; anonymous manifest verification and a
healthy core lab do not establish a full OpenWebUI workflow against the published
adapter/template pair.
