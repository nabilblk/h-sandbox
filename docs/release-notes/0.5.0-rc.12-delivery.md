## Local Deployment

The guarded upgrade selected only the explicitly identified `harakiri-k0s` lab
using `infra/k0s/harakiri.kubeconfig`. Helm release `harakiri` in namespace
`harakiri` is deployed at **revision 46**, advancing from 45. Web runs the rc.12
image index above on the existing arm64 node; its pod is ready and its runtime
image identity matches the published artifact.

The structured server-side dry run allowed only the web container image and
`image.web.tag` value to change. The upgrade reused all existing values and used
automatic rollback on failure. All 44 checked non-web deployment/statefulset,
configuration and secret resources were unchanged; no non-web running pod was
replaced during the rollout.

**The lab API, scheduler, template builder and chart remain rc.10.** This is
intentional: API behavior, database schema and chart templates are unchanged.
The new full image/chart distribution is published for consumers, but no unrelated
backend restart was required. Keycloak, provider/runtime workloads and the default
customer OpenShift context were not modified.

Private revision-45 Helm values, manifests, chart archive and before/after
resource evidence are retained outside Git in a mode-0700 operator backup
directory. Revision 45 is the rollback point for this image-only change, not a
general cross-schema rollback claim. Do not use bootstrap scripts for rollback.

## Limits

- Request deadlines default to 120 seconds in SDK rc.12. Long foreground commands
  need a larger request budget or detached execution. Local timeout/cancellation
  does not prove that remote execution stopped or permit blind replay.
- PostgreSQL workflow state belongs to the integrating application. A retained
  workspace preserves files, not process memory or command identity.
- Successful Harbor health/push checks do not establish physical disk or inode
  headroom. No host-level storage verification is claimed.
- npm provenance verification checks downloaded archive integrity and statement
  contents; it is not independent Sigstore signature verification.
