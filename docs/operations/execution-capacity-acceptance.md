## Recovery Exercise

The native harness takes a custom-format database backup of its isolated schema,
creates a sandbox, and takes a second matching backup. It restores the first
backup while leaving that native execution alive. Inventory discovers an
untracked execution, quarantines the organization and rejects another create
without dispatch. Restoring the matching second backup and reconciling allows
the known execution to be accounted for and then stopped normally.

Only the random test schema is restored. This is genuine PostgreSQL/native
inventory recovery, not a coordinated production volume, Vault-key or persistent
workspace restore exercise. Old mutation writers were never connected to this
test database.

## Reproduce

Follow the explicit environment and safety requirements in the
[operator runbook](execution-capacity.md#implementation-and-verification).

```bash
CAPACITY_TEST_REQUIRED=1 \
SANDBOX_TEST_DATABASE_URL=postgres://test-user@127.0.0.1:5432/test-db \
WORKSPACE_TEST_DATABASE_URL=postgres://test-user@127.0.0.1:5432/test-db \
pnpm test

HARAKIRI_E2E_MANAGED_SERVER=1 HARAKIRI_E2E_WEB_PORT=15184 \
pnpm exec playwright test tests/e2e/capacity.spec.ts \
  tests/e2e/docs-experience.spec.ts tests/e2e/authorization.spec.ts \
  tests/e2e/preview-readiness.spec.ts
```

Choose an unused web port. The reviewed run used an already-owned Vite server
on 15184 through `HARAKIRI_WEB_URL`. Browser captures and full command output
remain local artifacts; no credentials or full database backups belong in Git.
